# YMPlayer Project Audit

Дата: 2026-07-12
База аудита: `1.0.0-beta`, `versionCode 100`

Этот документ фиксирует состояние проекта после перехода от Poweramp-моста к
самостоятельному YMPlayer. После первичного аудита в 0.4.4 уже выполнена чистка
активного Poweramp-пути, поэтому документ одновременно фиксирует текущее
состояние и рабочий список следующих правок.

## Выполнено в 1.0.0-beta

- Подготовлен неотладочный release-вариант APK, совместимый с обновлением
  установленных тестовых версий без очистки данных.
- Видеоплеер получил реальный прогресс, время, seek и очередь текущего плюс
  один заранее разрешённый следующий поток.
- Панель управления и краткая подпись нового клипа разделены; автоматический
  переход показывает только название и исполнителя на пять секунд.
- Добавлена опциональная immersive-настройка клипов с восстановлением системных
  панелей при выходе и fallback для Android 10.
- Настройки перегруппированы по назначению, добавлен экспорт лога через
  MediaStore Downloads и окно «О приложении».
- Поиск защищён generation-token от устаревших результатов и получил
  компактные иконки действий.
- README переписан как пользовательская страница готового приложения.

## Выполнено в 0.5.0

- По предоставленному APK Кинопоиска для Android TV найден отдельный API Волны
  клипов, включая старт/продолжение `rotor/combined/session`, feedback и
  разрешение `playerId` через `frontend.vh.yandex.ru`.
- Добавлен отдельный полноэкранный Media3-плеер клипов. Он не смешан с рабочей
  аудиоочередью: при открытии отправляется штатный `STOP`, а обычная «Моя
  волна», кэш и плейлисты остаются в прежнем сервисе.
- Реализованы текущий плюс один следующий клип, фоновое разрешение следующего
  VH-манифеста, история назад, автоматическое продолжение и перезапуск пустой
  видеосессии.
- Оверлей показывает название и исполнителя и содержит предыдущий, play/pause,
  следующий, лайк и закрытие. Для клипов публикуется отдельная MediaSession с
  метаданными и обложкой.
- Лайк применяется к первому связанному `trackId`, обновляет глобальное «Мне
  нравится» и при включенной настройке запускает существующее постоянное
  кэширование аудиотрека. Видео постоянно не кэшируется.
- DRM не обходится: используется незашифрованный HLS/DASH или официальное
  превью, иначе клип пропускается.
- Исправить/подтвердить на устройстве: доступность видеоротора для конкретного
  региона и аккаунта, формат реальных VH-потоков, корректность `trackIds` для
  лайка и передача клиповой MediaSession в CarWebGuru.

## Выполнено в 0.5.1

- Неработающая кнопка полного выключения SideBar окончательно заменена на
  кнопку сна с иконкой луны.
- Возвращена подтвержденная исходным SideBar команда TS18/NWD:
  `ACTION_KEY_VALUE` с байтовым `extra_key_value=0`. После отправки SideBar
  сворачивается к краю экрана.
- Из APK удалены собственный shutdown-диалог, hidden API StatusBar/PowerManager,
  прямой `sys.powerctl`, vendor property bridge и эмуляция длинного power key.
- Рабочая отдельная кнопка перезагрузки сохранена; ее код выделен в компактный
  `Ts18RebootHelper` только с `RebootActivity` и launcher-mediated путями.
- Функционал SideBar зафиксирован: сон, перезагрузка, громкость/mute, home/back,
  вытягивание от края и автоскрытие. Без отдельной необходимости его больше не
  расширяем.

## Выполнено в 0.5.2

- Стартовый запрос Волны клипов повторно сверён с production-классами
  предоставленного Android TV APK; лишние nullable-поля удалены.
- Старт перебирает всю начальную выдачу до первого доступного потока, а
  следующий клип попадает в очередь только после успешного разрешения VH.
- Для current/next/history сохраняется породившая их rotor-сессия, поэтому
  feedback после автоматического перезапуска не отправляется в чужую сессию.
- Настоящие обложки liked-кэша вынесены в постоянные sidecar-файлы рядом с
  аудио. Скачанные аудиофайлы не модифицируются.
- Повторная синхронизация проверяет и догружает отсутствующие обложки даже для
  уже скачанных треков, не перекачивая исправное аудио.
- Логотип YMPlayer остается только fallback-картинкой интерфейса,
  MediaSession и уведомления; как обложка трека он не сохраняется.

## Выполнено в 0.4.4

- `CacheSyncService` больше не использует старый Poweramp-репозиторий.
  Синхронизация постоянного кэша идет через `player.YmpRepository` и остается
  ограниченной глобальным разделом "Мне нравится".
- `YandexTrackCache` перенесен из `dev.petrov.yaplay.poweramp` в
  `dev.petrov.yaplay.cache`; существующие каталоги кэша на устройстве не
  менялись.
- Удалены неиспользуемые классы Poweramp provider/tree-picker и строки
  `tree_picker_*`.
- Главный экран умеет читать embedded-обложку локального файла, когда у трека
  нет remote `cover_url`.
- В настройках добавлен явный статус Accessibility-службы YMPlayer для кнопки
  питания встроенного SideBar.

## Выполнено в 0.4.5

- AccessibilityService удален из YMPlayer после блокировки APK Google Play
  Protect на Redmi Note 14 Pro и с учетом ненадежности таких служб на TS18.
- Встроенный SideBar оставлен, но кнопка питания временно отключена и
  показывает пояснение вместо попытки вызвать power menu через Accessibility.
- Проект снова собирает один install-safe debug APK без выбора safe/full
  вариантов.

## Выполнено в 0.4.6

- Кнопка питания встроенного SideBar снова активна без AccessibilityService.
- Первый путь: запуск найденной в TS18 SystemUI активности
  `com.android.launcher/com.nwd.tools.reboot.RebootActivity`.
- Второй путь: системный Android `ACTION_REQUEST_SHUTDOWN` с подтверждением.
- Старый TS18 `extra_key_value=0` fallback удален, потому что на тестовой
  магнитоле он гасит экран вместо меню выключения/перезагрузки.

## Выполнено в 0.4.7

- Возвращена минимальная опциональная Accessibility-служба YMPlayer только для
  кнопки питания встроенного SideBar.
- Служба не включается автоматически и не является требованием плеера:
  настройки показывают статус и открывают системный экран специальных
  возможностей для ручного включения, как в исходном проекте SideBar.
- `YmpPowerMenuHelper` сначала пробует `GLOBAL_ACTION_POWER_DIALOG` через
  включенную службу, затем оставляет пути 0.4.6: TS18 `RebootActivity` и
  Android `ACTION_REQUEST_SHUTDOWN`.
- Служба не читает содержимое окон и не участвует в воспроизведении,
  авторизации Яндекса, поиске или кэше.

## Выполнено в 0.4.8

- Добавлены обходные пути кнопки питания встроенного SideBar на случай, если
  TS18-прошивка отключает опциональную Accessibility-службу YMPlayer.
- `YmpPowerMenuHelper` теперь пробует второй найденный reboot UI компонент:
  `com.nwd.toolallinone.app/com.nwd.tools.reboot.RebootActivity`.
- После прямых запусков helper отправляет штатные TS18 launcher-запросы
  `com.nwd.ACTION_REQUEST_START_ACTIVITY`, `com.nwd.action.ACTION_START_ACTIVITY`
  и `com.nwd.action.ACTION_START_NWD_ACTIVITY` с `extra_package_name` и
  `extra_class_name`, чтобы launcher сам открыл reboot UI.
- Прямой `com.nwd.action.ACTION_MCU_POWER_OFF` не используется: цель этой
  сборки - открыть запрос/подтверждение, а не выполнять немедленное действие.

## Выполнено в 0.4.9

- Подтверждено на устройстве, что TS18 launcher-mediated путь из 0.4.8
  открывает запрос на перезагрузку.
- AccessibilityService снова полностью удален из текущего APK: нет service в
  manifest, XML metadata, status row и кнопки открытия Accessibility settings.
- Кнопка питания встроенного SideBar теперь отвечает за запрос выключения через
  Android `ACTION_REQUEST_SHUTDOWN`.
- Для перезагрузки добавлена отдельная кнопка SideBar с иконкой reboot; она
  использует подтвержденный TS18 reboot UI path из 0.4.8.
- `com.nwd.action.ACTION_MCU_POWER_OFF` по-прежнему не используется, потому что
  это прямой firmware power-off event, а не запрос с подтверждением.

## Выполнено в 0.4.10

- Разобрана предоставленная TS18 3.1 прошивка
  `TS18.3.1_20260611.110603_WINDOW-THEME1(...)`: найдено, что штатное меню
  питания реализовано в Android SystemUI `GlobalActions`.
- Подтверждено по исходникам старого SideBar, что рабочий power-dialog путь там
  был `AccessibilityService.GLOBAL_ACTION_POWER_DIALOG`; fallback
  `extra_key_value=0` является TS18/NWD power-key и может только усыплять экран.
- Кнопка выключения встроенного SideBar теперь сначала пробует открыть
  `GlobalActions` через скрытый `StatusBarManager` и
  `IStatusBarService.showGlobalActionsMenu()`: для `StatusBarManager`
  проверяются оба имени метода, `showGlobalActions()` и
  `showGlobalActionsMenu()`. Затем остаётся старый `ACTION_REQUEST_SHUTDOWN`
  fallback.
- Кнопка перезагрузки не изменялась: оставлен подтвержденный TS18
  `RebootActivity` path.
- Прямой `ACTION_MCU_POWER_OFF` снова оставлен выключенным: в старом NWD дампе
  это событие состояния MCU power-off для подсистем, а не UI подтверждения.

## Выполнено в 0.4.11

- Найдена причина периодического лого YMPlayer вместо реальной обложки после
  сна/ACC: главный экран хранил свой кэш обложек, а MediaSession/notification
  после восстановления сервиса заново скачивали artwork из сети. При задержке
  сети CarWebGuru получал стандартное лого.
- Добавлен общий `YmpArtworkCache` для главного экрана, уведомления и
  MediaSession metadata.
- Добавлен ограниченный retry для текущей обложки после временной ошибки сети
  или SAF/USB-доступа.
- Decode remote/local artwork теперь ограничивает размер bitmap перед передачей
  в UI/notification/MediaSession.

## Выполнено в 0.4.12

- Повторно исследованы полный ext4-раздел TS18 3.1, заводской NWD launcher и
  SystemUI plugin. Подтверждено, что Android `ACTION_REQUEST_SHUTDOWN` защищен
  системным разрешением, а одиночный NWD power key может означать сон.
- Кнопка выключения встроенного SideBar теперь всегда показывает собственное
  подтверждение YMPlayer поверх экрана и не зависит от AccessibilityService.
- После подтверждения используется найденный в заводских NWD-библиотеках
  привилегированный мост `ACTION_SET_SYSTEM_PROP` для запроса
  `sys.powerctl=shutdown,userrequested`.
- Резервная power-команда передается как полная последовательность NWD
  `DOWN -> LONGPRESS -> UP` с `extra_key_type`, а не одиночный
  `extra_key_value=0`.
- Подтвержденный путь отдельной кнопки перезагрузки и код плеера не менялись.

## Карта проекта

- `app/src/main/java/dev/petrov/yaplay/MainActivity.java` - основной UI:
  главный экран, библиотека, поиск, настройки, локальный браузер файлов,
  выбор плейлистов, диагностика.
- `app/src/main/java/dev/petrov/yaplay/player/YmpPlaybackService.java` -
  MediaBrowser/MediaSession-сервис, очередь, "Моя волна", кэш, MediaPlayer,
  уведомление, восстановление состояния, keep-alive SideBar.
- `app/src/main/java/dev/petrov/yaplay/player/YmpRepository.java` - фасад
  между плеером, Yandex Music API, кэшем и локальными плейлистами.
- `app/src/main/java/dev/petrov/yaplay/ymusic/YandexMusicClient.java` -
  неофициальный клиент Yandex Music API: авторизация, плейлисты, поиск,
  rotor/My Wave, лайки/дизлайки, download-info.
- `app/src/main/java/dev/petrov/yaplay/player/LocalPlaylistStore.java` -
  локальные плейлисты, SAF-хранилища, локальное избранное, чтение метаданных.
- `app/src/main/java/dev/petrov/yaplay/player/EmbeddedSideBarService.java` -
  встроенный overlay SideBar с крупными кнопками.
- `app/src/main/java/dev/petrov/yaplay/player/SideBarHelper.java` - тихий
  keep-alive внешнего `com.ts18.sidebar`.
- `app/src/main/java/dev/petrov/yaplay/cache/` - постоянный и временный кэш
  аудиофайлов Яндекс Музыки.

## Работает, не трогать без необходимости

- Самостоятельный Android-плеер через MediaSession/MediaBrowser, уведомление
  и медиакнопки. Это основа для CarWebGuru и системного управления.
- "Моя волна": быстрый старт с первого трека, rotor feedback, дозагрузка
  следующего трека и аудио-предзагрузка. Менять только по результатам живых
  логов с устройства.
- Пассивное переключение источников: выбор волны/кэша/плейлиста останавливает
  текущее воспроизведение и ждет Play.
- Восстановление источника, очереди, последнего трека и позиции. По коду
  позиция сохраняется периодически и используется при следующем старте трека;
  дальше проверять только реальным тестом сна/пробуждения.
- Постоянный оффлайн-кэш только для глобального Яндекс-раздела "Мне нравится".
  Нелайкнутые треки должны оставаться только во временном playback cache.
- Раздельное качество для онлайн-воспроизведения и постоянного liked-кэша.
  Уже скачанные файлы не меняют качество до очистки или повторной синхронизации.
- Базовый поиск Яндекс Музыки: треки, альбомы, артисты, мини-обложки,
  воспроизведение результата, добавление найденного трека в Яндекс-плейлист.
- Базовая работа с Яндекс-плейлистами: список из аккаунта, выбор,
  воспроизведение, добавление текущего трека, создание плейлиста при добавлении,
  удаление с подтверждением.
- Локальные плейлисты: собственный SAF-браузер с чекбоксами, импорт файлов и
  папок, refresh папок, удаление треков, переименование, удаление обычных
  плейлистов, неудаляемое "Локальное избранное".
- Пропуск недоступных локальных файлов. Если в локальном плейлисте не осталось
  доступных файлов, плеер останавливается вместо бесконечных попыток.
- Передача bitmap-обложек и fallback-иконки в MediaSession/уведомление для
  CarWebGuru. Для liked-кэша 0.5.2 сначала используется постоянная настоящая
  обложка; fallback-логотип остается только отображаемым bitmap.
- Встроенный SideBar: overlay, вытягивание от края, крупные кнопки, настройка
  автоскрытия, сон, перезагрузка, громкость/mute/home/back. Сон использует
  подтвержденный TS18 key `0`; отдельная кнопка перезагрузки использует
  подтвержденные TS18 `RebootActivity`/launcher start-запросы.
  AccessibilityService и shutdown-эксперименты в текущем APK отсутствуют.
- Тихий keep-alive внешнего `com.ts18.sidebar`: `USER_PRESENT` в
  `SideBarHealthReceiver` и `CONFIG_CHANGED` без show/collapse extras. Это
  соответствует текущим заметкам проекта SideBar.

## Исправить

- Исправить: много фоновых задач создается через raw `new Thread`. Для обложек
  есть защита по последнему URL, а для My Wave есть часть guard-логики, но
  поиск, импорт, загрузка плейлистов и некоторые source-load операции могут
  дописывать статус после смены режима. Нужен единый executor и простые
  cancellation tokens для UI/источников.
- Исправить: имена настроек `sidebar_watchdog`, `sidebarWatchdogBox` уже не
  отражают смысл. Сейчас это управление встроенным SideBar, а не только
  watchdog. Переименовать при ближайшем безопасном рефакторинге.
- Подтвердить: проверить на магнитоле, что новая кнопка с луной гасит экран и
  после пробуждения SideBar остается свернутым у края. Дальнейшее исследование
  программного полного выключения закрыто.
- Исправить: `MainActivity`, `YmpPlaybackService`, `YandexMusicClient` и
  `LocalPlaylistStore` стали слишком большими. Резать их надо осторожно после
  стабилизации, иначе можно сломать уже рабочие сценарии.
- Исправить: нет автоматических тестов и CI. Пока контроль держится на
  `assembleDebug`, `lintDebug` и реальном устройстве. Минимум нужен CI на сборку
  debug/lint и небольшой набор тестов для чистых функций: качество, ключи
  треков, local playlist JSON, cache pruning.
- Подтвердить: проверить установку release APK поверх 0.5.2 на обоих целевых
  устройствах и убедиться, что токен, кэш и локальные плейлисты сохранены.

## Доделать

- Доделать экран текущей очереди: видеть список текущего источника, быстро
  перейти к треку, удалить локальный трек из очереди/плейлиста, понять что
  будет следующим.
- Доделать крупные локальные плейлисты: поиск внутри плейлиста, bulk-select,
  удаление пачкой, подробный diff при refresh папки, управление сохраненными
  storage roots.
- Доделать Яндекс-плейлисты: удаление отдельных треков из плейлиста,
  переименование плейлиста, возможно reorder, если API подтвердится.
- Доделать поиск: пагинация или "показать еще", более понятное действие для
  альбомов/артистов, отдельный экран результата вместо одного диалога при
  больших списках.
- Доделать качество: показать текущий выбранный профиль на главном экране или
  в статусе кэша, добавить действие "перекачать liked-кэш в новом качестве" с
  подтверждением.
- Доделать локальные обложки: сделать обогащение управляемым, показывать
  сколько файлов пропущено из-за read-only провайдера, не блокировать импорт
  больших папок долгими сетевыми lookup.
- Доделать MediaBrowser-дерево для внешних клиентов: сейчас системным
  браузерам видны базовые источники, но не вся библиотека Яндекс/локальных
  плейлистов.
- Доделать при необходимости: краткий структурированный отчёт о настройках
  качества и состоянии SideBar. Полный журнал с версией и моделью устройства
  уже сохраняется в `Downloads` в 1.0.0-beta.
